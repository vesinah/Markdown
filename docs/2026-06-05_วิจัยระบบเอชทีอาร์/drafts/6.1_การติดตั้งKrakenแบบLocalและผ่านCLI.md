## 1. บทนำและสเปกของระบบที่ต้องการ (Introduction & System Specifications)

ก่อนเริ่มกระบวนการติดตั้ง ผู้ปฏิบัติงานจำเป็นต้องเข้าใจก่อนว่า **Kraken** เป็นเอนจินรู้จำลายมือเขียน (Handwritten Text Recognition - HTR) แบบเปิดเผยซอร์สโค้ด (Open-source) ที่มีรากฐานดั้งเดิมพัฒนาสำหรับสภาพแวดล้อมแบบ Linux เป็นหลัก แม้ว่าปัจจุบันจะสามารถทำงานบน Windows ได้ แต่การรันบน Windows มักต้องอาศัยสภาพแวดล้อมเสมือนหรือเครื่องมือเสริมเพื่อคอมไพล์ไลบรารีที่จำเป็น

ในการใช้งาน Kraken เพื่อฝึกฝน (Training) หรือรันการรู้จำข้อความโบราณ โดยเฉพาะเอกสารอักษรไทย ขอม หรือธรรมล้านนา ซึ่งมีโครงสร้างพิกเซลที่ซับซ้อนและการซ้อนทับของอักขระหลายระดับ การมีหน่วยประมวลผลกราฟิก (GPU) ที่มีประสิทธิภาพจะช่วยประหยัดเวลาได้อย่างมหาศาล

### ตารางสเปกเครื่องคอมพิวเตอร์ขั้นต่ำและแนะนำ (System Hardware Requirements)

| รายการทรัพยากร | สเปกขั้นต่ำ (Minimum System) | สเปกแนะนำสำหรับการเทรน (Recommended System) |
|---|---|---|
| **หน่วยประมวลผล (CPU)** | Intel Core i5 / AMD Ryzen 5 (4 Cores ขึ้นไป) | Intel Core i7/i9 หรือ AMD Ryzen 7/9 (8 Cores+)|
| **หน่วยความจำ (RAM)** | 8 GB | 16 GB - 32 GB (หรือมากกว่าสำหรับการ compile arrow dataset ขนาดใหญ่) |
| **พื้นที่จัดเก็บข้อมูล** | SSD ว่างอย่างน้อย 20 GB | NVMe SSD ว่าง 100 GB ขึ้นไป (รองรับคลังรูปภาพ 300+ DPI และไฟล์ `.arrow`) |
| **การ์ดจอ (NVIDIA GPU)** | ไม่จำเป็น (รัน CPU ได้ แต่ช้ากว่า 10-20 เท่า) | NVIDIA GPU (RTX 3060/4060 หรือกลุ่ม Workstation) ที่มี **VRAM 8 GB ขึ้นไป (แนะนำ 12 GB+)** |
| **สถาปัตยกรรม CUDA** | - | CUDA Toolkit 11.8 หรือ 12.1+ พร้อม Driver ล่าสุด |
| **ระบบปฏิบัติการ** | Windows 10/11 Home/Pro หรือ Ubuntu 20.04 LTS | Ubuntu 22.04 LTS หรือ Windows 11 ผ่าน WSL 2 |

## 2. การเตรียมสภาพแวดล้อมระบบปฏิบัติการ (Operating System Preparation)

ในส่วนนี้จะอธิบายขั้นตอนการกำหนดค่าระบบปฏิบัติการ 3 รูปแบบหลัก ได้แก่ **Windows ผ่าน WSL 2** (แนะนำสูงสุดสำหรับผู้ใช้ Windows), **Windows Direct CLI** (ติดตั้งโดยตรงบนวินโดวส์), และ **Linux (Ubuntu)**

### 2.1 ทางเลือกที่ 1: ติดตั้งบน Windows ผ่าน WSL 2 (Windows Subsystem for Linux 2)
WSL 2 คือเทคโนโลยีที่ช่วยให้เราสามารถรัน Linux Kernel จริงภายใน Windows 10/11 ซึ่งจะช่วยหลีกเลี่ยงปัญหาความไม่เข้ากันของแพ็กเกจไบนารีระดับล่าง (Binary compilation issues) ได้อย่างดีที่สุด และรองรับการดึงพลัง GPU ผ่าน CUDA ได้อย่างสมบูรณ์แบบ

#### ขั้นตอนที่ 2.1.1: ตรวจสอบคุณสมบัติระบบและเปิดใช้งาน WSL
1. เปิด **PowerShell** ในโหมดสิทธิ์ผู้ดูแลระบบ (Run as Administrator)
2. สั่งติดตั้ง WSL พร้อมติดตั้ง Ubuntu เวอร์ชันล่าสุด โดยใช้คำสั่ง:
   ```powershell
   wsl --install
   ```
   *หมายเหตุ: หากเครื่องของท่านเคยติดตั้ง WSL ไว้แล้ว คำสั่งนี้จะแสดงคู่มือการใช้งาน หรือหากต้องการเจาะจงใช้ Ubuntu 22.04 สามารถรัน `wsl --install -d Ubuntu-22.04`*
3. **รีสตาร์ทคอมพิวเตอร์** ของท่านเพื่อให้ระบบ Windows โหลดโมดูล Virtualization Platform
4. หลังรีสตาร์ท หน้าต่างเทอร์มินัล Ubuntu จะปรากฏขึ้นโดยอัตโนมัติ ให้ทำการกำหนด **Username** และ **Password** ของระบบลินุกซ์ตามที่ต้องการ (แนะนำให้ตั้งรหัสที่จำง่ายแต่ปลอดภัย)

#### ขั้นตอนที่ 2.1.2: การอัปเดตสิทธิ์และการติดตั้งไลบรารีระบบใน WSL
เมื่อเข้าสู่ Ubuntu Terminal แล้ว ให้รันคำสั่งเหล่านี้เพื่ออัปเดตแพ็กเกจทั้งหมด และติดตั้งไลบรารีจำเป็นสำหรับการประมวลผลรูปภาพและคอมไพล์โค้ด C/C++:
```bash
# อัปเดตรายชื่อแพ็กเกจและอัปเกรดระบบ
sudo apt update && sudo apt upgrade -y

# ติดตั้งแพ็กเกจพัฒนา C++, Python และตัวช่วยประมวลผลรูปภาพ
sudo apt install build-essential python3 python3-pip python3-venv python3-dev -y
sudo apt install libtiff5-dev libjpeg-dev zlib1g-dev libfreetype6-dev liblcms2-dev libwebp-dev tcl8.6-dev tk8.6-dev python3-tk libharfbuzz-dev libfribidi-dev libgraphite2-dev -y
```

---

### 2.2 ทางเลือกที่ 2: ติดตั้งบน Windows Native Direct CLI (โดยไม่ใช้ WSL)
หากข้อจำกัดขององค์กรไม่สามารถเปิดใช้งานคุณลักษณะ Virtualization หรือ WSL 2 ได้ ผู้ใช้สามารถติดตั้ง Kraken โดยตรงบน Windows PowerShell หรือ CMD ได้ อย่างไรก็ตาม ผู้ใช้ต้องระมัดระวังในการติดตั้ง C++ Compiler เพื่อรองรับการคอมไพล์ไลบรารี Python บางตัว เช่น `shapely`, `pillow` หรือ C-extensions ของ Kraken

#### ขั้นตอนที่ 2.2.1: ติดตั้ง Python และ Git
1. ดาวน์โหลด Python 3.10 หรือ 3.11 (แนะนำรุ่น 64-bit) จากเว็บไซต์ทางการ [python.org](https://www.python.org/)
2. ในหน้าต่างติดตั้ง **ต้องทำเครื่องหมายเลือก "Add python.exe to PATH"** ก่อนคลิก Install Now
3. ดาวน์โหลดและติดตั้ง Git สำหรับ Windows เพื่อใช้รองรับการ clone สคริปต์เสริมและดาวน์โหลดโมเดลทดสอบ

#### ขั้นตอนที่ 2.2.2: ติดตั้ง Microsoft C++ Build Tools
เนื่องจาก Kraken และไลบรารีวิเคราะห์เรขาคณิต (เช่น Shapely หรือ PyTorch บางส่วน) พึ่งพาตัวเชื่อมคอมไพเลอร์ C++ บนระบบปฏิบัติการ Windows:
1. ดาวน์โหลด **Visual Studio Build Tools** จาก [visualstudio.microsoft.com/visual-cpp-build-tools/](https://visualstudio.microsoft.com/visual-cpp-build-tools/)
2. รันตัวติดตั้ง แล้วเลือกหัวข้อ **"Desktop development with C++"** (การพัฒนาเดสก์ท็อปด้วย C++)
3. กดปุ่ม Install ด้านล่างขวาและรอให้เสร็จสิ้น จากนั้นรีสตาร์ทเครื่องหนึ่งรอบ

### 2.3 ทางเลือกที่ 3: ติดตั้งบน Linux (Ubuntu 20.04 / 22.04 LTS หรือใหม่กว่า)
สำหรับเครื่องแม่ข่าย (Server) หรือเครื่อง PC ที่ติดตั้ง Linux โดยตรง ขั้นตอนนี้จะสั้นและเสถียรที่สุด

รันคำสั่งในเทอร์มินัลเพื่อเตรียมคอมไพเลอร์และไฟล์ส่วนหัวของระบบ (System Headers):
```bash
sudo apt update && sudo apt upgrade -y
sudo apt install build-essential python3 python3-pip python3-venv python3-dev git wget -y
sudo apt install libtiff5-dev libjpeg-dev zlib1g-dev libfreetype6-dev liblcms2-dev libwebp-dev tcl8.6-dev tk8.6-dev python3-tk libharfbuzz-dev libfribidi-dev libgraphite2-dev -y
```

## 3. การสร้างและเปิดใช้งานสภาพแวดล้อมเสมือน (Creating and Managing Python Virtual Environment)

การติดตั้งโมเดลการเรียนรู้เชิงลึก (Deep Learning Models) มีความอ่อนไหวสูงต่อเวอร์ชันของไลบรารี หากนำไปติดตั้งรวมกับ Python ส่วนกลางของระบบ อาจเกิดปัญหาความขัดแย้งของเวอร์ชัน (Dependency Version Conflicts) ดังนั้นการสร้างสภาพแวดล้อมเสมือน (Virtual Environment) จึงเป็น **กฎเหล็กที่ต้องปฏิบัติ** สำหรับทุกเครื่อง

### 3.1 การสร้างและเปิดใช้งานบน Linux หรือ Windows WSL 2
รันคำสั่งต่อไปนี้เพื่อเตรียมโฟลเดอร์โครงการและสร้างโฟลเดอร์เก็บไลบรารีเสมือน:

```bash
# 1. สร้างไดเรกทอรีโครงการ HTR และย้ายเข้าไปข้างใน
mkdir -p ~/htr_project
cd ~/htr_project

# 2. สร้าง Virtual Environment ชื่อว่า 'venv'
python3 -m venv venv

# 3. เปิดใช้งาน (Activate) สภาพแวดล้อมเสมือน
source venv/bin/activate

# 4. สังเกตการเปลี่ยนแปลงบน Prompt
# Prompt ของ Terminal จะเปลี่ยนเป็นมีคำว่า (venv) นำหน้า เช่น:
# (venv) user@computer:~/htr_project$
```

### 3.2 การสร้างและเปิดใช้งานบน Windows Native (PowerShell / Command Prompt)
ในกรณีติดตั้งบน Windows โดยตรง ให้เปิด PowerShell หรือ Command Prompt แล้วป้อนคำสั่ง:

```powershell
# 1. สร้างโฟลเดอร์เก็บโครงการ
mkdir C:\htr_project
cd C:\htr_project

# 2. สร้างสภาพแวดล้อมเสมือน
python -m venv venv

# 3. เปิดใช้งาน (สำหรับ Windows PowerShell)
# หากพบ Error เกี่ยวกับ Script execution ให้รัน Set-ExecutionPolicy Unrestricted -Scope Process ก่อน
.\venv\Scripts\Activate.ps1

# 4. เปิดใช้งาน (สำหรับ Command Prompt - CMD)
# .\venv\Scripts\activate.bat
```

## 4. การติดตั้ง PyTorch และการตั้งค่ารองรับ GPU (Installing PyTorch with GPU Support)

ไลบรารี **PyTorch** คือหัวใจหลักของ Kraken ที่ทำหน้าที่คำนวณเครือข่ายประสาทแบบ CNN และ LSTM หากเราติดตั้ง Kraken โดยตรงผ่าน `pip install kraken` ระบบจะพยายามดาวน์โหลดเวอร์ชัน CPU-only ของ PyTorch มาให้โดยปริยาย ซึ่งจะจำกัดการประมวลผลไว้เพียงบนหน่วยประมวลผลกลาง (CPU) ทำให้การฝึกฝนโมเดลช้ากว่าปกติถึง 10-20 เท่า

ขั้นตอนด้านล่างนี้คือกรรมวิธีติดตั้ง PyTorch รุ่นที่รองรับ GPU (ผ่านสถาปัตยกรรม NVIDIA CUDA) อย่างเป็นระบบ

### ขั้นตอนที่ 4.1: ตรวจสอบความพร้อมของไดรเวอร์การ์ดจอและเวอร์ชัน CUDA บน Host
เปิด Terminal (หรือ Command Prompt บนเครื่องหลัก) แล้วพิมพ์คำสั่ง:
```bash
nvidia-smi
```
ระบบจะแสดงสถานะการทำงานของ GPU เวอร์ชัน Driver และเวอร์ชันสูงสุดของ CUDA ที่ไดรเวอร์รองรับ (CUDA Version: เช่น 12.1 หรือ 12.5)

### ขั้นตอนที่ 4.2: ติดตั้ง PyTorch รุ่น CUDA ที่เหมาะสม
การติดตั้งไลบรารีต้องทำภายในสภาพแวดล้อมเสมือนที่ถูกเปิดใช้งานแล้ว `(venv)` เท่านั้น โดยเลือกชุดคำสั่งที่เข้ากันได้กับรุ่นของการ์ดจอและการติดตั้ง CUDA:

#### ทางเลือก A: สำหรับระบบที่รองรับ CUDA 12.1 (แนะนำสูงสุดสำหรับการ์ดจอ RTX ซีรีส์ 30 และ 40)
```bash
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu121
```

#### ทางเลือก B: สำหรับระบบเก่าที่รองรับ CUDA 11.8
```bash
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu118
```

#### ทางเลือก C: สำหรับการประมวลผลผ่าน CPU เท่านั้น (ไม่มีการ์ดจอแยก NVIDIA)
```bash
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cpu
```

## 5. ขั้นตอนการติดตั้ง Kraken ผ่าน pip (Installing Kraken via pip)

เมื่อกำหนดโครงสร้างไบนารีของ PyTorch ที่เชื่อมต่อ GPU เสร็จเรียบร้อยแล้ว ให้ดำเนินขั้นตอนการอัปเกรดเครื่องมือจัดเตรียมแพ็กเกจ (Build Tools) และติดตั้ง Kraken

```bash
# 1. ตรวจสอบให้มั่นใจว่า (venv) ยังเปิดใช้งานอยู่
# 2. อัปเกรดเครื่องมือติดตั้งแพ็กเกจพื้นฐานให้เป็นเวอร์ชันล่าสุด ป้องกันข้อผิดพลาดตอนสร้าง Wheel
pip install --upgrade pip setuptools wheel

# 3. สั่งติดตั้ง Kraken ผ่าน Python Package Index (PyPI)
pip install kraken
```

*หมายเหตุสำหรับการติดตั้งผ่าน Docker:* หากต้องการลดความยุ่งยากในสเตปของระบบและไลบรารี ผู้ใช้อาจเลือกใช้ Image ทางการจากผู้พัฒนาผ่าน Docker Hub ได้ด้วยคำสั่ง:
```bash
docker pull mittagessen/kraken:latest
```

## 6. การทดสอบและยืนยันการติดตั้ง (Testing and Verifying the Installation)

เมื่อการติดตั้งเสร็จสมบูรณ์ ผู้ปฏิบัติงานจำเป็นต้องยืนยันว่าโปรแกรมประยุกต์ Kraken และระบบย่อยทำงานได้ครบถ้วน รวมถึงความสามารถในการติดต่อใช้งาน GPU

### 6.1 ตรวจสอบเวอร์ชันผ่าน CLI
รันคำสั่งเหล่านี้เพื่อตรวจสอบเวอร์ชันของโปรแกรมควบคุมหลัก:
```bash
# ตรวจสอบเอนจินรู้จำ
kraken --version
# ตัวอย่างเอาต์พุตที่ควรได้: kraken 5.2.9 (หรือเวอร์ชันปัจจุบัน)

# ตรวจสอบเครื่องมือช่วยฝึกสอนโมเดล (ketos)
ketos --help
# ระบบควรแสดงรายการคำสั่งย่อย เช่น train, test, segment, segtrain, compile, trans
```

### 6.2 ตรวจสอบการใช้งานการ์ดจอ (CUDA / GPU Verification)
สร้างสคริปต์สั้น ๆ ใน Python เพื่อตรวจสอบการสตรีมพิกัดเทนเซอร์ไปที่ GPU ผ่าน PyTorch โดยป้อนคำสั่งดังนี้ใน terminal:
```bash
python -c "import torch; print('CUDA GPU Available:', torch.cuda.is_available()); print('Device Name:', torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'None')"
```
*ผลลัพธ์ที่ถูกต้องควรระบุสถานะเป็น `CUDA GPU Available: True` พร้อมตามด้วยชื่อการ์ดจอ NVIDIA ของท่าน หากระบบแสดงผลลัพธ์เป็น `False` ให้ตรวจสอบการจับคู่ไดรเวอร์ที่หัวข้อ Troubleshooting ด้านล่าง*

### 6.3 การทดสอบรันการทำงานจริง (Verification Smoke Test)
เพื่อรับประกันความพร้อมในการประมวลผลข้อความ ให้ดาวน์โหลดตัวอย่างภาพเพื่อทดสอบระบบแปลงภาพขาวดำ (Binarization) และการแบ่งส่วนบรรทัด (Segmentation)

```bash
# 1. ดาวน์โหลดภาพตัวอย่างลายเส้นขาวดำจากคลัง Kraken
wget https://raw.githubusercontent.com/mittagessen/kraken/main/tests/resources/bw.png -O test_image.png

# 2. รันคำสั่งแปลงภาพเป็นทวิภาค (Binarization) ด้วยอัลกอริทึม Sauvola หรือดีฟอลต์ของ Kraken
kraken -i test_image.png output_bw.png binarize

# 3. รันคำสั่งแบ่งส่วนบรรทัด (Layout Segmentation) เพื่อระบุตำแหน่งของเส้นฐานข้อความ (Baselines)
kraken -i output_bw.png output_seg.json segment

# 4. ตรวจสอบผลลัพธ์
# ระบบต้องสามารถสร้างไฟล์ output_bw.png และ output_seg.json ในไดเรกทอรีปัจจุบันโดยไม่มีโค้ดข้อผิดพลาด (Zero Exit Code)
echo "✅ ทดสอบระบบ Kraken สำเร็จ!"
```

## 7. คู่มือการวิเคราะห์และแก้ไขปัญหาที่พบบ่อย (Troubleshooting & Common Issues Guide)

ในระหว่างการรันคำสั่งติดตั้งหรือการจัดเตรียมโมเดล มักมีอุปสรรคทางเทคนิคเกิดขึ้นจากรุ่นของแพ็กเกจที่ไม่ตรงกันหรือสิทธิ์ในระบบลินุกซ์ ด้านล่างนี้คือแนวทางแก้ปัญหาเชิงลึกที่พบบ่อย:

### 7.1 ปัญหาด้านไลบรารีระบบและ Python Dependency

#### ❌ ปัญหา: `kraken: command not found` หลังการติดตั้ง
* **สาเหตุ:** เกิดจากการติดตั้งโดยลืมเปิดใช้งานสภาพแวดล้อมเสมือน หรือสคริปต์ของ Kraken ถูกเขียนลงในโฟลเดอร์ที่ไม่ถูกผูกไว้กับตัวแปรระบบ `PATH` ของ OS
* **แนวทางแก้ไข:** 
  1. ตรวจสอบว่าใน Prompt แสดง `(venv)` หรือไม่ ถ้าไม่ ให้รัน `source ~/htr_project/venv/bin/activate`
  2. หากติดตั้งแบบ `--user` บนลินุกซ์โดยตรง ให้ทำการเพิ่ม path ของ local bin เข้าในไฟล์ `~/.bashrc` โดยใช้คำสั่ง:
     ```bash
     export PATH=$PATH:$HOME/.local/bin
     source ~/.bashrc
     ```

#### ❌ ปัญหา: `Failed building wheel for shapely` หรือ `ModuleNotFoundError: No module named 'shapely.vectorized'`
* **สาเหตุ:** ไลบรารี Shapely ต้องการไฟล์สำหรับคอมไพล์ C-Library (GEOS) หากไม่มีในเครื่องจะรันไม่ผ่าน
* **แนวทางแก้ไข:** 
  * สำหรับ **Ubuntu/WSL2**: ติดตั้งไลบรารีระบบและเครื่องมือพัฒนาผ่าน apt:
     ```bash
     sudo apt install libgeos-dev -y
     pip install shapely --no-binary shapely
     ```
  * สำหรับ **Windows Native**: ติดตั้งผ่าน wheel สำเร็จรูปหรือใช้ pip เวอร์ชันใหม่สุดที่จัดการ pre-compiled wheels:
     ```powershell
     pip install --upgrade pip setuptools
     pip install shapely
     ```

#### ❌ ปัญหา: `ImportError: libGL.so.1: cannot open shared object file`
* **สาเหตุ:** ไลบรารีประมวลผลรูปภาพ OpenCV หรือ PIL (Pillow) พยายามเรียกใช้ฟังก์ชันกราฟิกของระบบลินุกซ์ แต่ในสภาพแวดล้อม WSL 2 แบบ Minimalist หรือ Ubuntu Server ไม่มี GUI/OpenGL ติดตั้งอยู่
* **แนวทางแก้ไข:** ติดตั้งไลบรารีกราฟิกและตัวแปรเสริมเสริมของ OpenCV บน Ubuntu:
  ```bash
  sudo apt update
  sudo apt install libgl1-mesa-glx libglib2.0-0 -y
  ```

---

### 7.2 ปัญหาด้านการประมวลผลผ่าน GPU และไดรเวอร์ CUDA

#### ❌ ปัญหา: `CUDA GPU Available: False` หรือ `UserWarning: CUDA initialization: CUDA unknown error`
* **สาเหตุ:** 
  1. คอมพิวเตอร์ของท่านไม่ได้ใช้การ์ดจอแยก NVIDIA
  2. ติดตั้งรุ่นของ PyTorch ไม่สอดคล้องกับ CUDA Driver ในระบบหลัก
  3. สภาพแวดล้อม WSL 2 ไม่สามารถมองเห็นหรือรับส่งคำสั่งไปที่การ์ดจอหลักของ Windows ได้
* **แนวทางแก้ไข:**
  1. ยืนยันรุ่น CUDA บนเครื่องหลักโดยพิมพ์ `nvidia-smi`
  2. ตรวจสอบเวอร์ชันของ PyTorch ที่เชื่อมโยง โดยพิมพ์ `pip list | grep torch`
  3. หากพบว่าไม่มีรุ่นบวกท้ายเช่น `+cu121` ให้ทำการถอนการติดตั้งและลงใหม่ด้วยดัชนีชี้ตรง:
     ```bash
     pip uninstall torch torchvision torchaudio -y
     pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu121
     ```
  4. สำหรับระบบ **WSL 2** ต้องมั่นใจว่าในคอมพิวเตอร์ Windows หลักได้ติดตั้งไดรเวอร์กราฟิกรุ่นล่าสุดจาก NVIDIA แล้ว (ตั้งแต่เวอร์ชัน Windows 10/11 เป็นต้นไป ไดรเวอร์ของ Windows จะมีคุณสมบัติรองรับการจำลอง GPU ลงสู่ WSL2 อัตโนมัติ โดยห้ามไปลงไดรเวอร์ NVIDIA ซ้ำซ้อนภายใน WSL 2 เด็ดขาด ให้ลงเพียงแค่ **CUDA Toolkit** ภายใน Ubuntu เท่านั้น)

#### ❌ ปัญหา: `CUDA out of memory` (OOM) ระหว่างการประมวลผลหรือเทรนโมเดล
* **สาเหตุ:** หน่วยความจำของการ์ดจอ (VRAM) ไม่เพียงพอต่อการจัดเก็บภาพบรรทัดและน้ำหนักค่าอนุพันธ์ของโครงข่ายประสาท (Gradients) ในการรัน Batch นั้น ๆ
* **แนวทางแก้ไข:**
  1. ปรับลดขนาดมัดข้อมูล (Batch Size) ในการใช้คำสั่ง `ketos train` โดยดีฟอลต์มักเป็น 32 หรือ 64 ให้ปรับลดเหลือ 8 หรือ 4:
     ```bash
     # ลด Batch size เหลือ 4 และจำกัดการประมวลผลแถว
     ketos train -B 4 -f xml path/to/data/*.xml
     ```
  2. สั่งปิดโปรแกรมอื่นที่กำลังใช้ GPU (เช่น Web Browser หลายแท็บ, วิดีโอสตรีมมิ่ง หรือ IDE พัฒนาโปรแกรมต่าง ๆ) เพื่อคืนพื้นที่ VRAM
  3. ตรวจสอบการจัดการทรัพยากรด้วยคำสั่ง `watch nvidia-smi` ในหน้าต่างเทอร์มินัลอื่นเพื่อสังเกตการขึ้นลงของหน่วยความจำแบบเรียลไทม์

### 7.3 ข้อจำกัดเฉพาะและคำแนะนำเชิงปฏิบัติการของ Kraken (Kraken Specific Anomalies)

#### ❌ ปัญหา: `KrakenInvalidModelException`
* **สาเหตุ:** ผู้ใช้พยายามนำโมเดลเก่าที่เคยเทรนในเวอร์ชันเก่า (เช่นไฟล์โมเดล `.clstm` หรือโมเดลจากเวอร์ชัน 3.x) มาโหลดใช้งานกับ Kraken เวอร์ชัน 4.x หรือ 5.x ซึ่งมีการอัปเกรดระบบจัดเก็บข้อมูลพารามิเตอร์และตัวเข้ารหัสอักขระใหม่
* **แนวทางแก้ไข:** 
  1. ตรวจสอบว่าโมเดลเดิมต้องการสัญกรณ์ใด
  2. หากต้องการนำโมเดลเก่ามาใช้ร่วมกับระบบใหม่ แนะนำให้รวบรวมไฟล์ Ground Truth (PAGE XML/ALTO XML) และทำการฝึกสอนตัวโมเดลใหม่ตั้งแต่ต้น (Retraining) บนเวอร์ชันปัจจุบัน เพื่อประสิทธิภาพและความทนทานที่ดีขึ้น หรือศึกษาการแปลงรูปแบบโมเดลผ่านยูทิลิตีระบบ

#### ❌ ปัญหา: เส้นขอบพิกเซลโพลีกอนบิดเบี้ยวหรือเกิดการลากบรรทัดข้ามคอลัมน์ (Polygonizer & Layout Issues)
* **สาเหตุ:** การประมวลผลเอกสารโบราณที่มีสภาพชำรุด มีรอยฉีกขาด หรือเอกสารที่มีสองคอลัมน์ในหน้าเดียว มักทำให้โมเดลตีความผิดพลาด
* **แนวทางแก้ไข:** 
  1. การประมวลผลก่อนเข้าสู่เอนจิน (Preprocessing): ปรับแนวเอียงของภาพ (Deskewing/Dewarping) และทำความสะอาดคราบมัว
  2. หากจำเป็นต้องกำหนดขอบเขตจัดวางหน้าหนังสือสมุดไทยหรือเอกสารใบลาน โครงการควรฝึกฝนโมเดลแบ่งแถวบรรทัดข้อความโดยเฉพาะ (Layout Segmentation Model) ผ่านคำสั่ง `ketos segtrain` โดยประยุกต์ใช้มาตรฐานการกำหนดแท็กของ **SegmOnto** เช่น กำหนดโซนบรรทัดหลัก และส่วนที่ไม่อ่าน (อาทิ อักขระยันต์และภาพวาดลายเส้นประกอบ)

## 8. ความเชื่อมโยงกับการประยุกต์ใช้ในโครงการ HTR อักษรไทยและอักษรขอมโบราณ (Thai / Khom HTR Implications)

ในการออกแบบกระบวนการติดตั้งและทดสอบนี้ มีบทเรียนทางเทคนิคที่เกี่ยวข้องกับอักษรโบราณของไทยโดยเฉพาะ 3 ประการหลัก:

### 8.1 การปรับขนาดความสูงอินพุตในแบบจำลอง (Input Height Specification in VGSL)
อักษรไทย ขอม หรือธรรมล้านนา มีโครงสร้างการจัดวางอักขระซ้อนแนวดิ่ง 4 ระดับ (เช่น ตัวสะกดบน สระบน พยัญชนะตัวตั้ง และตัวห้อยล่าง) หากเราใช้โครงข่ายตามการกำหนดค่าดีฟอลต์ของยุโรปที่มักบังคับบีบความสูงของภาพแถวให้อยู่ที่ `48` พิกเซล (ในข้อกำหนด VGSL สตริง: `[1,48,0,1...]`) รายละเอียดพิกเซลของอักขระแถวบนสุดและล่างสุดจะบิดเบี้ยวและเบลอจนนำมาซึ่งความผิดพลาดในการรู้จำ (High CER)
* **ข้อแนะนำเชิงปฏิบัติ:** ให้ทดลองปรับโครงสร้างเครือข่ายอินพุตเป็นความสูง **`80` พิกเซล** ขึ้นไป (เช่นปรับเป็น `[1,80,0,1...]`) เพื่อรักษาความสมดุลของอัตราส่วนพิกเซลอักษรซ้อนตั้ง

### 8.2 การสแกนสองทิศทาง (BiLSTM) ในการตรวจจับความสัมพันธ์แนวตั้ง
ในการเขียนอักษรขอมหรืออักษรธรรมล้านนา ตัวอักขระห้อยล่าง (ตัวเชิง) และเครื่องหมายพินทุมักจะปรากฏเยื้องไปด้านหลังพยัญชนะหลัก การใช้เครือข่ายจำลองประสาทแบบ **BiLSTM (Bidirectional LSTM)** ที่มีเลเยอร์สกัดลำดับอักษรทั้งจากซ้ายไปขวาและขวาไปซ้ายคู่ขนานกัน จะช่วยให้โมเดลมีจดจำคำสะกดได้ถูกต้องตามบริบทและลดอัตราความล้มเหลวในการตีความเครื่องหมายหรือพินทุใต้บรรทัด

### 8.3 การเร่งความเร็วการฝึกสอนผ่านไฟล์ชุดข้อมูล Apache Arrow (`.arrow`)
สำหรับโครงการขนาดใหญ่ที่มีรูปชิ้นส่วนภาพข้อความใบลานและไฟล์กำกับข้อความระดับหลายหมื่นบรรทัด การเปิดอ่านไฟล์เดี่ยวซ้ำ ๆ ในกระบวนการเทรนจะก่อให้เกิดภาระงานเขียนอ่านข้อมูลของดิสก์หนักมาก (Disk I/O bottleneck) 
* **ข้อแนะนำเชิงปฏิบัติ:** วิศวกรข้อมูลควรทำการรวบรวมและคอมไพล์ชุดข้อมูลให้อยู่ในรูปไฟล์ไบนารีเดี่ยวด้วยคำสั่ง `ketos compile` ก่อนการส่งเทรน:
  ```bash
  ketos compile -f xml -o thaikhom_dataset.arrow path/to/xml/files/*.xml
  ```
  สเตปนี้จะช่วยให้ระบบสามารถอ่านชุดข้อมูลเข้าสู่ GPU ได้ทันทีโดยไม่ติดขัด ส่งผลให้ประสิทธิภาพการฝึกฝนโมเดล HTR บน local PC ทำงานได้เสร็จเร็วยิ่งขึ้นกว่าร้อยละ 30

## 9. ตารางคำสั่ง Kraken/Ketos ที่ใช้บ่อยในกระบวนการทำงาน (Command Reference Table)

| กลุ่มการทำงาน | รูปแบบคำสั่ง CLI | คำอธิบายและพารามิเตอร์หลัก |
|---|---|---|
| **ตรวจสอบระบบ** | `kraken --version` | ตรวจสอบรุ่นเวอร์ชันของซอฟต์แวร์ Kraken |
| **แปลงภาพขาวดำ** | `kraken -i <input.png> <output.png> binarize` | แปลงภาพถ่ายสเปกตรัมสีเทาเป็นภาพทวิภาค (ขาวดำ) |
| **แบ่งส่วนบรรทัด** | `kraken -i <input.png> <output.json> segment` | หาพิกัดเส้นฐานและรูปหลายเหลี่ยมรอบแถวอักษร |
| **สกัดตัวอักษร HTR** | `kraken -i <input.png> <output.txt> ocr -m <model.mlmodel>` | ใช้โมเดลวิเคราะห์ภาพและทำนายข้อความเป็นไฟล์อักษร |
| **คอมไพล์บิวด์ข้อมูล** | `ketos compile -f xml -o <dataset.arrow> <path/*.xml>` | แพ็กโครงสร้างรูปและป้ายกำกับข้อความเป็นฐานข้อมูล Arrow |
| **เริ่มฝึกสอนโมเดล** | `ketos train -f binary -o <model_name> <dataset.arrow>` | เริ่มฝึกฝนโมเดลรู้จำข้อความใหม่ด้วยชุดข้อมูล Arrow |
| **เทรนต่อยอดโมเดล** | `ketos train -i <pre_model.mlmodel> -f binary -o <new_model> <dataset.arrow>` | ทำการ Fine-tuning ปรับปรุงโมเดลเดิมด้วยชุดข้อมูลใหม่ |
| **ประเมินความแม่นยำ** | `ketos test -m <model.mlmodel> -f binary <test_dataset.arrow>` | วัดค่า CER (Character Error Rate) ของโมเดลบนชุดข้อมูลทดสอบ |
