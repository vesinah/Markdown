ในกระบวนการอนุรักษ์และปริวรรตเอกสารโบราณด้วยเทคโนโลยีการรู้จำข้อความลายมือเขียน (Handwritten Text Recognition หรือ HTR) ความท้าทายประการสำคัญที่นักวิชาการด้านมนุษยศาสตร์ดิจิทัล (Digital Humanities) นักประวัติศาสตร์ และนักอักษรศาสตร์มักเผชิญร่วมกันคือข้อจำกัดทางเทคนิคในการเข้าถึงเครื่องมือและการเขียนคำสั่งควบคุมผ่านภาษาคอมพิวเตอร์ แม้ว่าการเขียนโค้ดเพื่อควบคุมเฟรมเวิร์กการเรียนรู้เชิงลึก (Deep Learning Frameworks) จะมอบความยืดหยุ่นในการพัฒนาสถาปัตยกรรมระดับลึกที่มีประสิทธิภาพสูงเพียงใดก็ตาม แต่ความซับซ้อนของการตั้งค่าสภาพแวดล้อมการทำงาน การจัดการหน่วยประมวลผลกราฟิก (GPU) ตลอดจนการพัฒนาโครงข่ายประสาทเทียมก็ยังคงเป็นอุปสรรคสำคัญที่ทำให้เครื่องมือเหล่านี้ไม่สามารถนำมาใช้แพร่หลายในหมู่นักวิจัยทั่วไปได้ ด้วยเหตุนี้ ซอฟต์แวร์ประยุกต์และเว็บแอปพลิเคชันที่ทำงานบนการปฏิสัมพันธ์แบบกราฟิกกับผู้ใช้ (Graphical User Interface หรือ GUI) หรือที่เรียกว่าแนวทางการพัฒนาแบบไร้โค้ด (No-code Path) จึงกลายเป็นสะพานเชื่อมชิ้นสำคัญที่ช่วยให้นักศึกษาและนักวิชาการจดหมายเหตุสามารถเข้าถึงเทคโนโลยีระดับสูงได้โดยตรง

แพลตฟอร์มการทำงานแบบไร้โค้ดช่วยให้นักวิจัยสามารถดำเนินงานวิจัยได้ทุกขั้นตอน ตั้งแต่ขั้นตอนการนำเข้าไฟล์ภาพ การวิเคราะห์และจำแนกเค้าโครงหน้าเอกสาร (Document Layout Analysis) การปรับแต่งแก้ไขพิกัดเส้นบรรทัดฐาน (Baseline Detection) และโพลีกอนห่อหุ้มบรรทัด (Polygon Masking) ด้วยตนเอง ไปจนถึงการปริวรรตป้อนข้อมูลตัวอักษรเทียบภาพเพื่อสร้างชุดข้อมูลความจริงเชิงประจักษ์ (Ground Truth) และกระบวนการรันฝึกสอนแบบจำลองปัญญาประดิษฐ์ตลอดจนดาวน์โหลดแบบจำลองที่ผ่านการฝึกฝนสำเร็จรูปนำมาประยุกต์ใช้งาน ในบรรดาแพลตฟอร์มที่ได้รับการยอมรับและใช้เป็นมาตรฐานการทำงานทางอักษรศาสตร์ดิจิทัลระดับนานาชาติในปัจจุบัน eScriptorium และ Transkribus ถือเป็นระบบหลักสองขั้วที่มีกระบวนการทำงานและปรัชญาการพัฒนาที่แตกต่างกันอย่างชัดเจน โดย eScriptorium มุ่งเน้นการเป็นซอฟต์แวร์เสรีและเปิดเผยรหัสต้นฉบับ (Free and Open-source Software) ที่สามารถติดตั้งบนระบบท้องถิ่นหรือเซิร์ฟเวอร์ส่วนตัวได้โดยไม่มีค่าใช้จ่าย ในขณะที่ Transkribus มีรูปแบบการให้บริการบนคลาวด์คอมพิวติ้ง (Cloud Computing) ภายใต้การบริหารจัดการของสมาคมจดหมายเหตุดิจิทัลแห่งสหภาพยุโรป ซึ่งเพียบพร้อมด้วยโมเดลกลางจำนวนมากและเอนจินประมวลผลประสิทธิภาพสูง การทำความเข้าใจขั้นตอนการติดตั้ง การใช้งานและการฝึกสอนในทั้งสองระบบจะช่วยให้นักวิจัยสามารถตัดสินใจเลือกใช้แพลตฟอร์มที่สอดคล้องกับข้อจำกัดด้านงบประมาณ ขอบเขตข้อมูลเชิงกายภาพ และนโยบายการจัดเก็บข้อมูลขององค์กรได้อย่างเหมาะสมและมีประสิทธิผลสูงสุด

## 6.1 การทำงานบนระบบ eScriptorium + Kraken

eScriptorium เป็นหนึ่งในผลผลิตสำคัญของการขับเคลื่อนด้านมนุษยศาสตร์ดิจิทัลเสรีซึ่งได้รับการพัฒนาขึ้นโดยสถาบันวิจัยชั้นนำของฝรั่งเศส (อาทิ PSL Research University และสถาบัน École Nationale des Chartes) เพื่อให้เป็นส่วนติดต่อผู้ใช้ผ่านเว็บแอปพลิเคชันที่สะดวกในการจัดการชุดข้อมูลและกระบวนการทำงานของเอนจินจำลองเอชทีอาร์ตัวสำคัญอย่าง Kraken [1] ซึ่งเป็นเอนจินโอเพนซอร์สประสิทธิภาพสูงสำหรับการตรวจจับพิกเซลและการถอดความตัวอักษร การบูรณาการ eScriptorium และ Kraken ช่วยให้นักวิจัยสามารถทำงานบนหน้าต่างเว็บที่ใช้งานง่ายผ่านระบบเครือข่ายอินทราเน็ตหรืออินเทอร์เน็ต โดยมีสิทธิ์เข้าควบคุมข้อมูลดิบของเอกสารโบราณอย่างสมบูรณ์แบบโดยไม่ต้องส่งไฟล์ภาพสำคัญออกไปนอกเครือข่ายความมั่นคงของสถาบัน

### 6.1.1 การติดตั้งระบบเบื้องต้นและการนำเข้ารูปภาพหน้าเอกสารโบราณ
การเริ่มต้นปฏิบัติงานบนระบบ eScriptorium สามารถทำได้สองรูปแบบหลัก ได้แก่ การใช้งานผ่านเซิร์ฟเวอร์ส่วนกลางของสถาบันวิจัยที่ให้บริการแก่สาธารณะ หรือการติดตั้งระบบขึ้นมาเป็นเซิร์ฟเวอร์ของตนเองเพื่อใช้งานภายในส่วนบุคคลหรือหน่วยงาน โดยกระบวนการติดตั้งระดับท้องถิ่นที่แนะนำและมีความเสถียรสูงสุดคือการใช้งานผ่านเทคโนโลยีคอนเทนเนอร์ (Containerization) ด้วยซอฟต์แวร์ Docker และ Docker Compose นักวิจัยต้องทำการโคลนโครงการไฟล์ตั้งค่าระบบของ eScriptorium มาไว้ในเครื่องเซิร์ฟเวอร์ปลายทางที่มีหน่วยประมวลผลกราฟิกของเอ็นวีเดีย (NVIDIA GPU) และติดตั้งไลบรารีควบคุม CUDA จากนั้นใช้คำสั่ง `docker-compose up -d --build` เพื่อสั่งให้ระบบทำการสร้างคอนเทนเนอร์และเชื่อมโยงระบบฐานข้อมูล PostgreSQL ตลอดจนระบบจัดระเบียบงานประมวลผลเบื้องหลังด้วย Celery และ Redis เมื่อคอนเทนเนอร์ทั้งหมดเริ่มทำงานเป็นปกติแล้ว นักวิจัยสามารถเข้าสู่ระบบ eScriptorium ผ่านเว็บเบราว์เซอร์ทางพอร์ตเครือข่ายที่กำหนดไว้ (โดยทั่วไปคือ http://localhost:8000 หรือหมายเลขไอพีของเซิร์ฟเวอร์) และลงทะเบียนเข้าใช้งานบัญชีผู้ควบคุมระบบเริ่มต้นผ่านการตั้งค่าผู้ใช้งานระดับสูงสุด (Superuser)

หลังจากการลงทะเบียนเข้าสู่ระบบและสร้างบัญชีปฏิบัติงานเรียบร้อยแล้ว ขั้นตอนแรกในการดำเนินโครงงานเอชทีอาร์คือการสร้างโครงการวิจัย (Project) โดยการคลิกเลือกเมนู "Projects" บนแถบควบคุมหลักด้านซ้ายแล้วกรอกชื่อโครงการวิจัย คำอธิบาย ตลอดจนกำหนดขอบเขตสิทธิ์การเข้าถึงข้อมูลของสมาชิกในทีมวิจัย จากนั้นสร้างเอกสาร (Document) ภายใต้โครงการนั้นๆ โดยระบุประเภทอักขระเป้าหมาย เช่น อักษรขอมบนใบลาน หรืออักษรไทยโบราณบนกระดาษ เมื่อสร้างเอกสารเรียบร้อยแล้ว ระบบจะเปิดโอกาสให้นำเข้าภาพเอกสารโบราณในหน้าย่อย "Images" โดย eScriptorium สนับสนุนการนำเข้าภาพเอกสารลายมือเขียนโบราณหลายรูปแบบ อาทิ ไฟล์ภาพนามสกุล TIFF, PNG, และ JPEG รวมถึงการนำเข้าผ่านระบบส่งผ่านข้อมูลคลังดิจิทัลมาตรฐานสากล (International Image Interoperability Framework หรือ IIIF Manifest) การอัปโหลดสามารถทำได้โดยการลากไฟล์ภาพมาวางบนพื้นที่อัปโหลดบนหน้าเว็บโดยตรง หรือเลือกการอัปโหลดไฟล์บีบอัดประเภท ZIP ที่บรรจุรูปภาพและสร้างคิวสำหรับการนำเข้าข้อมูลขนาดใหญ่ ระบบจะนำภาพเหล่านั้นเข้าสู่กระบวนการตรวจรับและเก็บรักษาไว้ในพื้นที่คลังเก็บสื่อ (Media Storage) ของระบบฐานข้อมูลอย่างเป็นระบบเพื่อเตรียมความพร้อมสำหรับขั้นตอนการวิเคราะห์ในลำดับถัดไป

### 6.1.2 การใช้งานระบบช่วยจัดแบ่งบรรทัดข้อความอัตโนมัติด้วยแบบจำลองเค้าโครงของ Kraken
เมื่อไฟล์ภาพเอกสารโบราณได้รับการบันทึกเข้าสู่ฐานข้อมูลระบบแล้ว การดำเนินงานขั้นถัดมาคือการวิเคราะห์เค้าโครงของเอกสาร (Document Layout Analysis) เพื่อจำแนกสัดส่วนภาพและตรวจหาเส้นบรรทัดฐานในการเขียนอักขระ ในสภาพแวดล้อมแบบไร้โค้ดของ eScriptorium นักวิจัยสามารถเรียกใช้แบบจำลองวิเคราะห์เค้าโครงสำเร็จรูปที่ได้รับการฝึกฝนมาล่วงหน้าของ Kraken ซึ่งมีชื่อแบบจำลองมาตรฐานคือ `blla.mlmodel` (Baseline and Layout Analysis model) [1] โดยแบบจำลองชนิดนี้ทำงานบนสถาปัตยกรรมโครงข่ายประสาทเทียมแบบคอนโวลูชันที่ประมวลผลจำแนกประเภทพิกเซล (Pixel-wise Semantic Segmentation) เพื่อแยกแยะพิกเซลในภาพถ่ายเอกสารโบราณออกเป็นกลุ่มขอบเขตพื้นที่ตัวอักษร (Text Regions) และแนวเส้นฐานหลักที่ตัวอักษรเขียนพาดผ่าน (Baselines)

ขั้นตอนการรันระบบวิเคราะห์เค้าโครงอัตโนมัติ เริ่มจากการคลิกทำเครื่องหมายเลือกไฟล์ภาพในหน้าต่าง "Images" ของเอกสารที่ต้องการวิเคราะห์ จากนั้นกดเลือกเมนูย่อย "Segment" บนแถบคำสั่งควบคุมระบบจะแสดงหน้าต่างข้อความสำหรับตั้งค่าการทำงาน โดยผู้ใช้สามารถระบุการเลือกเซกเมนเตอร์ (Segmenter) และเลือกนำเข้าแบบจำลองเซกเมนต์จากรายการแบบจำลองที่มีอยู่ในระบบ หรือทำการอัปโหลดไฟล์แบบจำลอง `blla.mlmodel` ขึ้นสู่ระบบผ่านทางปุ่มโหลดไฟล์จำลองส่วนตัว ในหน้าตั้งค่านี้มีตัวเลือกการกำหนดทิศทางการตรวจจับอักขระและการตั้งค่าลักษณะจำเพาะ เช่น ทิศทางจากซ้ายไปขวา (Left to Right) หรือทิศทางบนลงล่าง เมื่อตรวจสอบค่าเรียบร้อยแล้วให้กดปุ่ม "Segment" เพื่อส่งชุดภาพเข้าสู่ระบบคิวประมวลผล Celery เพื่อให้หน่วยประมวลผลกราฟิกของเซิร์ฟเวอร์ทำการคำนวณและสกัดพิกัดเวกเตอร์ของแนวบรรทัดฐานและขอบเขตพื้นที่บรรทัดทีละภาพโดยอัตโนมัติ ซึ่งหลังจากระบบทำงานเสร็จสิ้นแล้ว จะแสดงผลสถานะเสร็จสิ้นบนหน้าแถบความคืบหน้า และสร้างโครงสร้างเส้นประกอบบรรทัดขึ้นมาซ้อนทับภาพถ่ายเอกสารโบราณในหน้าจอแก้ไขเค้าโครง

### 6.1.3 การปรับแก้เส้นบรรทัดฐานด้วยมือและการวาดเส้น Baselines
การวิเคราะห์เค้าโครงโดยระบบอัตโนมัติของ `blla.mlmodel` [1] แม้จะมีความแม่นยำสูงในภาพถ่ายเอกสารที่สะอาดพิมพ์ตรงสม่ำเสมอ แต่สำหรับจารึกคัมภีร์ใบลานอักษรขอมที่มีขนาดแคบยาว เส้นแบ่งธรรมชาติบิดเบี้ยว รอยจารตื้นลึกไม่เท่ากัน หรือกระดาษสมุดไทยโบราณที่มีการบันทึกด้วยลายมือเขียนหวัดเชิงเฉียงเอียง ระบบมักเกิดความผิดพลาดในการตรวจจับแนวบรรทัดและไม่สามารถระบุแนวเส้นได้อย่างสมบูรณ์ ปัญหาที่พบเป็นประจำ ได้แก่ การเชื่อมแนวเส้นข้ามระหว่างบรรทัดที่เป็นคนละข้อความ การระบุสระและวรรณยุกต์ลอยฟ้าหลุดลอยแยกเป็นบรรทัดใหม่ และการมองข้ามเชิงอักษรขอมที่ซ้อนตัวเป็นพยัญชนะซ้อนแนวตั้ง (Vertical Stacking) ลงไปเบียดบรรทัดล่าง นักวิจัยจึงจำเป็นต้องเปิดหน้าต่างบรรณาธิการเลย์เอาต์ (Layout Editor) ใน eScriptorium เพื่อดำเนินการปรับแต่งและปรับปรุงพิกัดเวกเตอร์เหล่านั้นด้วยมือ

ภายในหน้าต่าง Layout Editor ของ eScriptorium นักวิจัยจะสามารถมองเห็นแนวเส้นอ้างอิงบรรทัดฐานสีต่างๆ ที่ถูกวาดและซ้อนทับอยู่บนภาพถ่ายต้นฉบับ เส้นหลักที่สำคัญที่สุดคือเส้นบรรทัดฐาน (Baseline) ซึ่งเป็นพิกัดเส้นฐานที่ลากพาดผ่านแนวล่างสุดของตัวอักษรปกติ (ไม่รวมเชิงอักษรล่างหรือสระอุ สระอู) และขอบเขตโพลีกอนห่อหุ้มบรรทัด (Polygon Mask) ซึ่งจำลองขอบเขตเนื้อที่รอบข้างเส้นบรรทัดฐานเพื่อกักเก็บพิกเซลอักษรรอบด้านในบรรทัดเดียวกัน หากพบว่าเส้นบรรทัดฐานที่ระบบตรวจจับไว้มีความคลาดเคลื่อน นักวิจัยสามารถใช้เครื่องมือวาดเส้นใหม่เพื่อเพิ่มเส้น ตกแต่งปุ่มขยับตำแหน่งเพื่อปรับแนวโค้งเอียงตามจารจารึก ลบเส้นส่วนเกินที่ตัดข้ามเขต หรือใช้เครื่องมือตัดแบ่ง (Cut Tool) เพื่อแยกเส้นบรรทัดที่ยาวติดต่อกันเกินไป นอกจากนี้ยังสามารถรวมเส้น (Join Tool) เพื่อเชื่อมโยงพิกัดที่ขาดออกจากกันให้เป็นแนวเดียวกัน และจัดระเบียบประเภทแนวบรรทัด (เช่น กำหนดให้เป็นบรรทัดทั่วไป หรือพื้นที่ภาพ) พร้อมทั้งแก้ไขลำดับของการอ่าน (Reading Order) ผ่านปุ่มควบคุมระเบียบลำดับการอ่าน เพื่อให้แน่ใจว่าการประมวลผลการอ่านอักษรจะลื่นไหลสอดคล้องตามหลักอักขรวิธีจากซ้ายไปขวาและบนลงล่างอย่างถูกต้อง

### 6.1.4 หน้าต่างการถอดความและการเชื่อมโยงข้อมูล
หลังจากการตรวจหาเส้นบรรทัดฐานและขอบเขตโพลีกอนห่อหุ้มบรรทัดได้รับการจัดระเบียบและปรับปรุงแก้ไขความถูกต้องแบบสมบูรณ์ 100% แล้ว ขั้นตอนถัดมาคือการปริวรรตข้อความถอดความคู่ขนานไปกับส่วนของภาพบรรทัดย่อย (Line-level image) เพื่อเตรียมการสร้างข้อมูลความจริงเชิงประจักษ์ (Ground Truth) eScriptorium ออกแบบหน้าจออินเทอร์เฟซสำหรับการปริวรรต (Transcription Interface) ที่แบ่งแยกการแสดงผลหน้ากระดาษเอกสารโบราณออกเป็นแถวบรรทัดย่อยๆ ทีละเส้นอย่างเป็นเอกเทศ เมื่อผู้วิจัยคลิกที่บรรทัดใดบรรทัดหนึ่ง ระบบจะขยายภาพตัดเฉพาะของแนวขอบเขตโพลีกอนของบรรทัดนั้นแสดงผลขึ้นทางหน้าจอด้านบน และเปิดช่องป้อนข้อความทางด้านล่างเพื่อให้ผู้วิจัยพิมพ์อักขระที่ถอดได้ลงไปโดยตรง

ในการถอดความอักษรโบราณขอมและไทยโบราณ ผู้วิจัยต้องปฏิบัติตามมาตรฐานการปริวรรตเชิงโครงสร้างดั้งเดิม (Diplomatic Transcription) ที่เข้มงวด โดยจำต้องคัดลอกสะกดตัวอักษรทุกตัว รวมถึงตัวเขียนสะกดที่ผิดพลาด ตัวขอมซ้อนรูปเชิงตั้ง (Vertical Stacking) คำย่อ หรือเครื่องหมายแสดงเสียงโบราณตามที่เขียนอยู่ในเอกสารจริงทุกประการ ห้ามมิให้ทำความสะอาดหรือแปลงเป็นภาษาเขียนปัจจุบัน เพราะโมเดลเอชทีอาร์ระดับพิกเซลภาพจำเป็นต้องอาศัยคู่ภาพและตัวอักษรถอดความที่ตรงกันเชิงกายภาพที่สุดเพื่อสร้างค่าน้ำหนักจำแนกพิกเซลตัวอักษร ในกรณีที่หน้าเอกสารมีบางจุดอ่านไม่ออก ชำรุด ขาดหาย หรือมีรอยไหม้เกรียมของวัสดุใบลาน ผู้วิจัยต้องพิมพ์สัญลักษณ์สากลตามที่กำหนดไว้ในการตั้งค่าโครงการ เช่น การใส่เครื่องหมายวงเล็บเหลี่ยมหรือสัญลักษณ์พิเศษเฉพาะโครงการเพื่อหลีกเลี่ยงการป้อนป้ายระบุอักษรที่ไม่มีรูปทรงพิกเซลชัดเจนให้แก่โมเดล ข้อมูลที่ผู้วิจัยกรอกลงในช่องข้อความถอดความจะถูกบันทึกและจับคู่พิกัดพิกเซลเวกเตอร์ของเส้นบรรทัดฐานบรรทัดนั้นโดยอัตโนมัติเข้าสู่ฐานข้อมูล ทำให้เป็นชุดคู่ภาพและข้อความที่พร้อมสำหรับการนำไปใช้ฝึกสอนต่อไป

### 6.1.5 ขั้นตอนการรันโปรแกรมฝึกสอนโมเดลรู้จำตัวเขียน Kraken HTRผ่านหน้าเว็บ
เมื่อนักวิจัยทำการถอดความและปริวรรตเอกสารโบราณได้ปริมาณข้อมูลที่มากพอสมควรแล้ว (ซึ่งตามมาตรฐานทางสถิติทัศน์จำเป็นต้องใช้ข้อความถอดความคู่ภาพที่มีคุณภาพสูงอย่างน้อย 800 ถึง 1,500 บรรทัดขึ้นไปสำหรับการเริ่มปรับแต่งแบบจำลองเฉพาะอักขระ) นักวิจัยจะสามารถเริ่มต้นรันกระบวนการฝึกสอนตัวประมวลผลรู้จำคำ (Recognizer Training) ของ Kraken ได้ผ่านหน้าอินเทอร์เฟซของ eScriptorium โดยตรงโดยไม่ต้องเขียนโค้ดภาษาไพทอนแม้แต่บรรทัดเดียว

ขั้นตอนการดำเนินการเริ่มต้นจากการสืบค้นไปยังเมนู "Images" ของตัวเอกสารหลัก จากนั้นให้เลือกภาพทั้งหมดที่ผ่านการถอดความและตรวจสอบพิกัดความถูกต้องอย่างสมบูรณ์แล้ว คลิกเลือกเมนู "Train" บนแถบคำสั่งปฏิบัติงานและกดเลือกชนิดการเทรนเป็นแบบ "Recognizer" ระบบจะปรากฏกล่องข้อความสำหรับตั้งค่าการฝึกอบรม โดยผู้ใช้จำเป็นต้องกำหนดพารามิเตอร์สำคัญหลายประการ:
1. การระบุชื่อไฟล์จำลองผลลัพธ์ (Model Name): ให้ระบุชื่อที่สื่อความหมายชัดเจน เช่น `khmer_palm_leaf_htr_v1` และหลีกเลี่ยงการทำเครื่องหมายถูกในช่อง "Overwrite the existing model file" เพื่อป้องกันระบบเข้าไปเขียนทับไฟล์โมเดลตั้งต้นจนสูญเสียน้ำหนักดั้งเดิม
2. การระบุสัดส่วนแบ่งทดสอบข้อมูล (Validation Split): กำหนดสัดส่วนตามทฤษฎีวิชาการมาตรฐาน เช่น ค่าอัตราส่วน 0.1 หรือ 0.2 (หมายถึงการสุ่มดึงร้อยละ 10 หรือ 20 ของชุดข้อมูลถอดความทั้งหมดออกไปเป็นชุดข้อมูลสำหรับประเมินผลการเรียนรู้ในแต่ละรอบฝึกสอน ส่วนที่เหลือร้อยละ 80 หรือ 90 นำไปเทรนโมเดล)
3. การเลือกใช้แบบจำลองฐาน (Base Model): แนะนำอย่างยิ่งให้คลิกเลือกนำเข้าไฟล์แบบจำลอง HTR อักษรโบราณที่มีอยู่เดิมหรือแบบจำลองกลุ่มภาษาโบราณที่คล้ายคลึงกันขึ้นสู่คลังโมเดล เพื่อเริ่มต้นการฝึกสอนแบบเรียนรู้ถ่ายโอน (Transfer Learning) ซึ่งช่วยย่นเวลาการฝึกสอนและใช้ข้อมูลจำนวนน้อยกว่าในการเรียนรู้การปรับแนวเส้นเทียบกับระดับการฝึกสอนใหม่จากศูนย์ (Train from scratch)

ภายหลังจากตรวจสอบพารามิเตอร์ตั้งค่าทั้งหมดเสร็จสิ้นแล้ว ให้คลิกปุ่ม "Train" ระบบ eScriptorium จะสั่งจัดโครงสร้างข้อมูลคู่ภาพข้อความของภาพที่เลือก สกัดพิกเซลย่อยออกจากแนวเส้นโพลีกอน และส่งคิวงานคำนวณเข้าสู่ Celery Task Queue โดยมีเซิร์ฟเวอร์ย่อยดึงงานไปรันการคำนวณปรับน้ำหนักตัวแปรโครงข่ายประสาทเทียมผ่านเฟรมเวิร์กการเรียนรู้ของ Kraken บนระบบ GPU ทันที

### 6.1.6 การติดตามความคืบหน้าของการฝึกสอนและดาวน์โหลดไฟล์ผลลัพธ์ `.mlmodel`
ในขณะที่โมเดลกำลังดำเนินการเทรน นักวิจัยสามารถสืบค้นและติดตามสถานะความคืบหน้าของการฝึกสอนได้ผ่านหน้าต่างควบคุมหลัก "Models" ของหน้าต่างประวัติการจัดทำเอกสาร หรือเข้าสู่หน้าจอรวมศูนย์ "My Models" ของผู้ใช้ ระบบจะแสดงสถานะการคำนวณที่กำลังดำเนินอยู่พร้อมทั้งอัปเดตกราฟระดับค่าความผิดพลาดระดับอักขระ (Character Error Rate หรือ CER) ในแต่ละรอบการเทรน (Epochs) การลู่เข้าหาคำตอบที่ดีที่สุดของโมเดลสามารถดูได้จากความชันของกราฟค่าความสูญเสีย (Loss) และค่า CER บนชุดประเมินผล (Validation Set) ที่มีแนวโน้มลดลงอย่างต่อเนื่อง หากพบว่าค่าผิดพลาดคงที่ไม่เปลี่ยนแปลงหรือมีทิศทางพุ่งสูงสวนทาง (Overfitting) ระบบการเทรนของ Kraken จะมีการตั้งค่าหยุดกระบวนการก่อนกำหนดโดยอัตโนมัติ (Early Stopping) เพื่อรักษาน้ำหนักโมเดลที่ดีที่สุดเอาไว้

เมื่อแบบจำลองรู้จำ HTR ของ Kraken ได้รับการฝึกสอนเสร็จสมบูรณ์เรียบร้อยแล้ว แถบสถานะการประมวลผลจะแจ้งสัญลักษณ์เสร็จสิ้นอย่างสมบูรณ์ และสร้างไฟล์ผลลัพธ์แบบจำลองใหม่ที่ประมวลผลได้ดีที่สุดขึ้นมาในรายการโมเดลส่วนตัว นักวิจัยสามารถดาวน์โหลดไฟล์นี้มาบันทึกไว้ในเครื่องคอมพิวเตอร์ของตนเองได้โดยตรงโดยไฟล์ดังกล่าวจะมีนามสกุลไฟล์เป็น `.mlmodel` (เช่น `khmer_palm_leaf_htr_v1.mlmodel`) ไฟล์แบบจำลองจำเพาะอักษรใบลานหรือสมุดไทยตัวนี้ จะเป็นโครงข่ายอรรถประโยชน์ที่สมบูรณ์แบบ ซึ่งนักวิจัยสามารถนำไปอัปโหลดขึ้นระบบ eScriptorium เครื่องอื่นเพื่อกดปุ่มสั่งถอดความคัมภีร์หน้าใหม่ๆ ได้ในทันที หรือนำไปประยุกต์สั่งรันการทำงานผ่านคำสั่งคอมมานด์ไลน์ด้วยยูทิลิตี้ `ketos` บนเครื่องคอมพิวเตอร์ที่ติดตั้ง Kraken [1] สแตนด์อะโลนภายนอกเพื่อความรวดเร็วในการถอดความเอกสารโบราณปริมาณมหาศาลโดยไม่ต้องเข้าหน้าอินเทอร์เฟซ

## 6.2 การทำงานบนระบบ Transkribus

Transkribus เป็นแพลตฟอร์มการรู้จำลายมือเขียนจดหมายเหตุระดับโลกที่ได้รับการพัฒนาขึ้นโดยได้รับงบประมาณสนับสนุนจากโครงการวิจัยและนวัตกรรม Horizon 2020 ของสหภาพยุโรป ภายใต้การดูแลร่วมกันของมหาวิทยาลัยและสถาบันชั้นนำ เช่น University of Innsbruck ตลอดจนปัจจุบันได้รับการบริหารจัดการเชิงวิชาการโดยสมาคมสหกรณ์จดหมายเหตุดิจิทัลยุโรป READ-COOP SCE แพลตฟอร์ม Transkribus ให้บริการในลักษณะสถาปัตยกรรมแบบไคลเอนต์และเซิร์ฟเวอร์บนคลาวด์คอมพิวติ้งที่พัฒนาขึ้นเพื่อรองรับขั้นตอนการถอดความเอกสารโบราณที่หลากหลาย ตั้งแต่การวิเคราะห์หน้าเพจ การวาดเส้นฐาน การปริวรรตข้อมูล และระบบสำคัญอย่างการส่งข้อมูลคำสั่งเทรนโมเดลเอชทีอาร์เฉพาะตัวบนหน่วยประมวลผลขนาดใหญ่ของคลาวด์เซิร์ฟเวอร์โดยไม่ต้องพึ่งพาการซื้ออุปกรณ์การประมวลผลระดับสูงด้วยตนเอง

### 6.2.1 วิธีการสร้างบัญชีผู้ใช้และการจัดระเบียบเอกสารเป็นคอลเลกชันดิจิทัล
การเริ่มต้นทำงานบน Transkribus จำเป็นต้องมีการเชื่อมต่ออินเทอร์เน็ตเพื่อเข้าถึงระบบฐานข้อมูลกลางและคิวประมวลผลคลาวด์ นักวิจัยเริ่มแรกโดยการสมัครสร้างบัญชีผู้ใช้งานผ่านเว็บไซต์ทางการของ Transkribus จากนั้นเข้าสู่หน้าต่างแพลตฟอร์มผ่านเว็บแอปพลิเคชัน Transkribus Web Lite/AI Lab หรือดาวน์โหลดซอฟต์แวร์ไคลเอนต์ระดับสูงสำหรับการปฏิบัติตำแหน่งบรรณาธิการอย่างละเอียด ซึ่งเรียกว่า Transkribus eXpert มาติดตั้งบนเดสก์ท็อป

เมื่อเข้าสู่ระบบการทำงานแล้ว โครงสร้างหลักในการจัดเก็บเอกสารจะอิงอยู่บนระบบคอลเลกชันดิจิทัล (Collection) ซึ่งทำหน้าที่เสมือนกับชั้นวางสมุดเอกสารโบราณ นักวิจัยสามารถสร้างคอลเลกชันขึ้นมาใหม่โดยการตั้งชื่อคอลเลกชันและกำหนดสิทธิ์ผู้ใช้ร่วมกันในโครงการ หลังจากที่จัดตั้งคอลเลกชันเรียบร้อยแล้ว ให้เริ่มดำเนินการนำเข้าไฟล์ภาพของสมุดไทยหรือใบลานโบราณ โดยการอัปโหลดไฟล์ภาพผ่านอินเทอร์เฟซของตัวโปรแกรม Transkribus รองรับฟอร์แมตไฟล์ทั่วไปและระบบไฟล์ PDF ขนาดใหญ่ รวมถึงระบบการอัปโหลดผ่าน URL ภาพหรือ IIIF Manifest เมื่อส่งภาพขึ้นคลาวด์เซิร์ฟเวอร์แล้ว ตัวระบบจะรันงานการแปลงภาพและเตรียมความพร้อมในการจำแนกแผ่นงานลงในสมุดบันทึกรายการ (Document) ภายในระบบประมวลผลส่วนตัวคลาวด์เพื่อให้สมาชิกของทีมทำงานตรวจสอบได้เรียลไทม์

### 6.2.2 การทำความสะอาดเลย์เอาต์ด้วยเอนจินวิเคราะห์ความร่วมมือ CITlab และตรวจบรรทัด Baseline
ภายหลังจากการยืนยันสิทธิการนำเข้าภาพเอกสารเรียบร้อยแล้ว ขั้นตอนถัดมาคือการทำความสะอาดเลย์เอาต์หน้าเอกสารผ่านกระบวนการจำแนกเค้าโครงอัตโนมัติ ซึ่งในแพลตฟอร์ม Transkribus ได้รับการพัฒนาและบูรณาการเครื่องมือตรวจจับที่มีความแม่นยำสูงอย่างเอนจินวิเคราะห์ความร่วมมือ CITlab (Center for Image and Signal Processing, University of Rostock) เอนจินวิเคราะห์เค้าโครงของ CITlab ขับเคลื่อนโดยโครงข่ายประสาทเทียมระดับลึกเชิงความหมายแบบ ARU-Net (Attention Relation U-Net) ซึ่งเป็นสถาปัตยกรรมที่รวมกลไกความสนใจเชิงพื้นที่และการคำนวณลักษณะเด่นพิกเซลในการสกัดแนวเส้นฐานบรรทัด (Baseline Detection) และอาณาบริเวณข้อมูลได้อย่างยอดเยี่ยมบนเอกสารประวัติศาสตร์โบราณ

ในการรันตรวจจับเลย์เอาต์อัตโนมัติ นักวิจัยสามารถเปิดใช้งานหน้าเมนู "Tools" ในตัวโปรแกรม เลือกกำหนดขอบเขตขีดความสามารถการแบ่งส่วนบรรทัดและภูมิภาค (Layout Analysis) และเลือกใช้โมเดลสำเร็จรูปสำหรับการหาแนวเส้นบรรทัดฐานของ CITlab จากนั้นคลิกปุ่ม "Run" เพื่อส่งชุดภาพประมวลผลบน GPU เซิร์ฟเวอร์ ระบบจะคำนวณสกัดพิกัดเชิงเส้นบรรทัดฐานสีแดงหรือน้ำเงิน (ตามการแสดงผลอินเทอร์เฟซ) พร้อมพื้นที่โพลีกอนรอบบรรทัดครอบคลุมอักษรทั้งหมดในแนว และสร้างความเชื่อมโยงของภาพย่อยบรรทัดเข้ากับระบบดัชนีของเอกสารเพื่อเตรียมความพร้อมในการเข้าสู่การทำงานขั้นปริวรรตต่อไป

### 6.2.3 การปรับแก้เส้นบรรทัดฐานด้วยมือผ่านโปรแกรมแก้ไขของ Transkribus
แม้ระบบประมวลผล ARU-Net ของเอนจิน CITlab จะมีความล้ำสมัยในการเรียนรู้แนวบรรทัดฐาน แต่ลักษณะทางกายภาพที่ซับซ้อนของคัมภีร์ใบลานอักษรขอมที่มีขอบวัสดุไม่เรียบ รอยพับชำรุด หรือสมุดไทยที่บันทึกข้อมูลแนวตารางหรือโครงร่างที่มีอักษรซ้อนทับกันมาก ก็ยังคงก่อให้เกิดความคลาดเคลื่อนในการตัดแบ่งเส้น แนวเส้นฐานที่หักมุมหรือวิ่งผิดทิศทางของการอ่านจะเป็นอุปสรรคต่อขั้นตอนถัดไปอย่างมาก ดังนั้น นักวิจัยจึงจำเป็นต้องเปิดแท็บแก้ไขแนวบรรทัดฐาน (Layout Editor / Baseline Editor) ในโปรแกรม Transkribus eXpert หรือ Web GUI เพื่อทำการปรับค่าพิกัดเหล่านี้ด้วยมือให้ได้คุณภาพแบบ Ground Truth 100%

ในอินเทอร์เฟซการจัดการเค้าโครงของ Transkribus ผู้ใช้สามารถจัดการปรับปุ่มเลื่อนเพื่อขยับทิศทาง ลบแนวบรรทัด ปรับแก้พิกัดล่างให้แนบสนิทไปตามขอบล่างของพยัญชนะตัวเขียนฐานหลัก (Baseline) และลากพาดผ่านสัญลักษณ์ตัวสะกดอย่างสอดคล้องกัน เครื่องมือ Baseline Editor ประกอบด้วยชุดฟังก์ชันการเพิ่มขอบเขตของพอยต์เวกเตอร์ การแบ่งแยกบรรทัด (Split Line) การรวมบรรทัด (Merge Line) และการจัดทำโซนขอบเขตที่ต้องการถอดความพิเศษ (Structure Type) เช่น กำหนดให้เป็นพารากราฟ หัวข้อเรื่อง ขอบข้อความ หรือคำบันทึกเสริมขอบทางกายภาพ พร้อมกันนี้จำเป็นต้องวิเคราะห์ลำดับการประมวลผลการอ่าน (Reading Order) เพื่อให้แน่ใจว่าระบบประมวลผลดรรชนีของตัวอักษรเรียงลำดับถูกบทถูกข้อตามต้นฉบับดั้งเดิมก่อนสั่งบันทึกการปรับปรุงข้อมูลความปลอดภัยลงบนฐานข้อมูลคลาวด์

### 6.2.4 การพิมพ์คลังข้อมูล Ground Truth เทียบอักขระและการถอดความ
เมื่อการปรับปรุงพิกัดแนวบรรทัดฐานและการจัดระบบเลย์เอาต์มีความแม่นยำไร้ข้อคลาดเคลื่อนแล้ว ขั้นตอนสำคัญลำดับต่อมาในการปั้นโมเดลเอชทีอาร์คุณภาพสูงคือการทำปริวรรตจัดสร้างฐานข้อมูลความจริงเชิงประจักษ์ (Ground Truth) ในอินเทอร์เฟซการถอดความของ Transkribus หน้าต่างการทำงานจะแยกออกเป็นสองส่วนหลักอย่างชัดเจน ได้แก่ หน้าต่างแสดงภาพตัดย่อยบรรทัดปัจจุบันที่ระบบแยกพิกเซลตามขอบเขต Baseline และหน้าต่างป้อนข้อความเทียบตัวอักษรทีละบรรทัด (Transcription Panel) ที่จัดเตรียมไว้ให้ผู้ใช้ป้อนเนื้อหาตามลำดับบรรทัดการอ่าน

การถอดความในแพลตฟอร์ม Transkribus สำหรับงานวิจัยภาษาประวัติศาสตร์ไทยและขอมโบราณจะต้องปฏิบัติตามกฎกติกาวิทยาศาสตร์จารึกและระบบคลังคำศัพท์กลางอย่างเข้มแข็ง ผู้ถอดความต้องจารึกตัวเขียนตามจริง (Diplomatic Transcription) โดยคงลักษณะอักขรวิธี อักษรควบกล้ำ (Ligatures) พยัญชนะซ้อนรูปโบราณและอักษรขอมทับซ้อนแนวดิ่งที่แท้จริง [2] หลีกเลี่ยงการปรับแก้รูปแบบสะกดให้เป็นภาษาปัจจุบันเพื่อป้องกันการรบกวนสัญญาณภาพพิกเซลระหว่างประมวลผล ในอินเทอร์เฟซของ Transkribus ยังมีแผงระบบปุ่มลัดพิมพ์อักขระพิเศษและเครื่องหมายโบราณที่ผู้ใช้อาจสร้างปุ่มจำลองไว้เพื่อความรวดเร็วในการปริวรรต และยังเปิดหน้าการใช้งานพยากรณ์เบื้องต้นเพื่อช่วยลดภาระการถอดความประหยัดเวลาด้วยระบบช่วยปริวรรตด้วยโมเดลกลางที่มีอยู่ในระบบคลาวด์ก่อนหน้า การกรอกข้อมูลถอดความจะต้องสมบูรณ์สม่ำเสมอในทุกหน้าเอกสารเพื่อให้ได้คู่ข้อมูลภาพบรรทัดและข้อความที่ตรงตามเป้าหมายเพื่อเป็นหัวเชื้อฝึกอบรมระดับสูง

### 6.2.5 ขั้นตอนการตั้งค่าส่งเทรนโมเดลเฉพาะทางด้วย PyLaia หรือ HTR+ บนบริการคลาวด์ GPU
เมื่อสะสมข้อมูล Ground Truth ที่มีคุณภาพเสถียรได้ในปริมาณมากพอสมควรแล้ว นักวิจัยสามารถสั่งตั้งค่าส่งเทรนโมเดลลายมือเขียนเฉพาะทาง (Custom Model Training) บนแพลตฟอร์ม Transkribus ผ่านหน้าต่าง AI Lab หรืออินเทอร์เฟซเดสก์ท็อป โดย Transkribus สนับสนุนสถาปัตยกรรมเอนจินประมวลผลสองตัวหลัก ได้แก่ PyLaia [2] ซึ่งเป็นเฟรมเวิร์ก HTR ที่ออกแบบบนฐานการพัฒนาของ PyTorch มุ่งเน้นการคำนวณที่ยืดหยุ่นด้วยกลไก CNN และ BiLSTM ร่วมกับการจัดคิวคำนวณ CTC Loss และเอนจิน HTR+ (HTR Plus) ซึ่งเป็นสถาปัตยกรรมโครงข่ายประสาทเทียมประสิทธิภาพสูงที่จัดรูปแบบการแปลงลำดับของหน้าอย่างหนาแน่น

ขั้นตอนการดำเนินส่งฝึกสอนตัวแบบจำลองลายมือเขียนมีกระบวนการดังนี้:
1. การสร้างและระบุชุดหน้ากระดาษเป้าหมาย: นักวิจัยเข้าไปที่เมนูการฝึกอบรม (Train Model) จากนั้นเลือกตั้งชื่อโมเดลเฉพาะตัวและทำรายการระบุหน้ากระดาษที่เป็นข้อมูล Ground Truth เพื่อใช้เป็นชุดฝึกสอน (Train Set) และเลือกหรือสั่งสุ่มแยกหน้าบางส่วน (โดยปกติร้อยละ 10 หรือ 20) ไปเป็นชุดหน้าทดสอบคำนวณผลการปรับน้ำหนัก (Validation Set)
2. การระบุชนิดของเอนจิน: เลือกระหว่างเอนจิน PyLaia [2] หรือ HTR+ โดยในปัจจุบันระบบ Transkribus แนะนำให้ใช้ PyLaia เนื่องจากเป็นเอนจินแบบโอเพนซอร์สมาตรฐานที่มีความยืดหยุ่นในการจูนและปรับปรุงต่อเนื่อง
3. การเลือกแบบจำลองเริ่มต้น (Base Model): นักวิจัยสามารถเลือกนำแบบจำลอง HTR คัมภีร์อักษรโบราณขอมหรือไทยใบข่อยที่เผยแพร่เป็นสาธารณะหรือมีอยู่ในสิทธิ์การใช้งานมาเป็นฐานการเรียนรู้ถ่ายโอน (Transfer Learning) ซึ่งวิธีการถ่ายโอนนี้ส่งผลดีอย่างยิ่งในการลดระยะเวลาการอบรมและประหยัดการใช้จำนวนบรรทัดตั้งต้น
4. การกำหนดระดับรอบและพารามิเตอร์การประมวลผล: ตั้งค่าจำนวนรอบการฝึกสอน (เช่น 150 ถึง 250 Epochs) การระบุพารามิเตอร์ของระบบหยุดประมวลผลก่อนเวลาเพื่อป้องกันปัญหาแบบจำลองฟิตเกินขอบเขตข้อมูล (Early Stopping parameter) จากนั้นคลิกปุ่มส่งงาน (Submit)

ระบบ Transkribus จะส่งออกข้อมูลโครงสร้างข้อความและภาพต้นฉบับเวกเตอร์ขึ้นสู่คิวคลาวด์ประมวลผล และเปิดใช้งานคอมพิวเตอร์คลัสเตอร์ GPU ประสิทธิภาพสูงของ READ-COOP ในการคำนวณฝึกสอนในทันที ซึ่งกระบวนการคำนวณทั้งหมดจะดำเนินไปโดยเบื้องหลังทำให้นักวิจัยสามารถปิดโปรแกรมหรือดำเนินการปริวรรตหน้าเพจแผ่นอื่นต่อได้โดยไม่ต้องเสียทรัพยากรคอมพิวเตอร์ส่วนตัว

### 6.2.6 การประเมินและดาวน์โหลดแบบจำลองที่ผ่านการฝึกฝน
ภายหลังจากการประมวลผลการคำนวณเสร็จสิ้น นักวิจัยจะได้รับการแจ้งเตือนความคืบหน้าของงานสำเร็จผ่านทางหน้าจอโปรแกรมหรืออีเมลส่วนตัว ในแถบประวัติโมเดลระบบจะวาดกราฟสถิติจำลองการประเมินเพื่อรายงานความคืบหน้า ประกอบด้วยตัวเลขค่าความผิดพลาดระดับอักขระ (Character Error Rate หรือ CER) ของระบบฝึกสอนเปรียบเทียบกับระบบทดสอบความแม่นยำในชุดตรวจประเมินผล ซึ่งค่า CER ที่ยอมรับได้สำหรับงานระดับวิชาการประวัติศาสตร์โดยทั่วไปควรมีค่าน้อยกว่าร้อยละ 5 ถึง 10 บนชุดทดสอบอิสระเพื่อความมั่นใจในคุณภาพการใช้งานจริง

แบบจำลองที่ได้จะถูกจัดเก็บไว้ในฐานคลังข้อมูลส่วนตัวของผู้ใช้งานใน Transkribus นักวิจัยสามารถนำโมเดลที่ผ่านการประเทรนและจูนด้วยข้อมูลของใบลานขอมหรือสมุดข่อยไทยตัวนี้ ไปสั่งรันการถอดความอัตโนมัติ (Inference/Transcribe) กับภาพหน้ากระดาษแผ่นใหม่หรือเล่มใหม่ทั้งเล่มในบัญชีได้ทันทีเพียงแค่เลือกหน้า คลิกเครื่องมือ HTR เลือกโมเดลที่ได้รับการจูน และสั่งรันระบบ ระบบคลาวด์จะสกัดข้อความทำนายของภาพแผ่นใหม่ส่งออกมาให้ตรวจสอบและปรับแต่งเพิ่มเติมประหยัดเวลากว่าการเขียนมือตั้งแต่ต้นอย่างมีนัยสำคัญ แม้ว่าการนำโมเดลออกไปใช้งานนอกระบบของ Transkribus จะมีข้อจำกัดด้านกรรมสิทธิ์ (ยกเว้นการดึงข้อมูลผ่าน Transkribus API หรือข้อกำหนดเฉพาะในโมเดล PyLaia [2] ที่ผู้ใช้อาจสามารถติดต่อเพื่อขอรับไฟล์ข้อมูลค่าน้ำหนักเวกเตอร์นำมาสกัดใช้รันแบบออฟไลน์ผ่านคอมพิวเตอร์ของสถาบันได้ภายใต้สิทธิ์ผู้ดูแลคอลเลกชัน)

## สรุป

ในการเลือกใช้วิธีปฏิบัติตามแนวทางการพัฒนาแบบไร้โค้ด (No-code / GUI Path) เพื่อสร้างและฝึกโมเดล HTR สำหรับภาษาขอมและภาษาไทยโบราณ แพลตฟอร์ม eScriptorium และ Transkribus ต่างมอบโซลูชันที่มีขีดความสามารถที่น่าพึงพอใจและผ่านการพิสูจน์แล้วในระบบจดหมายเหตุระดับสูงของนานาชาติ ทว่าความแตกต่างด้านการบริหารทรัพยากรและเงื่อนไขการเป็นเจ้าของข้อมูลถือเป็นปัจจัยชี้ขาดสำคัญในการประเมินประสิทธิภาพการเลือกใช้งานสำหรับนักวิชาการแต่ละกลุ่ม

ข้อเปรียบเทียบเชิงลึกระหว่างสองแพลตฟอร์มไร้โค้ดสรุปได้ดังนี้:

| ประเด็นการประเมิน | eScriptorium + Kraken [1] | Transkribus (PyLaia/HTR+) [2] |
|:---|:---|:---|
| **รูปแบบการติดตั้ง** | โอเพนซอร์ส ติดตั้งภายในระบบท้องถิ่น (Local Host) หรือระบบคิวเซิร์ฟเวอร์สถาบัน (Docker) | ระบบคลาวด์ เข้าใช้งานผ่านหน้าเว็บหรือแอปพลิเคชันเดสก์ท็อปสำเร็จรูป (Transkribus eXpert) |
| **กรรมสิทธิ์และการควบคุมข้อมูล** | สมบูรณ์ 100% ข้อมูลรูปภาพและแบบจำลองทั้งหมดจัดเก็บภายในเครื่อง ไม่มีความเสี่ยงเรื่องข้อมูลรั่วไหล | ข้อมูลถูกนำไปประมวลผลบนคลาวด์เซิร์ฟเวอร์ส่วนกลางของ READ-COOP เว้นแต่บริการระบบ On-Premises |
| **การใช้ทรัพยากรคำนวณ (ฮาร์ดแวร์)** | ต้องจัดหาและดูแลเซิร์ฟเวอร์ที่มีหน่วยประมวลผล GPU สมรรถนะสูงของตนเองในการเทรนโมเดล | ใช้ทรัพยากร GPU บนระบบคลาวด์ส่วนกลางของผู้ให้บริการเป็นหลัก ไม่เป็นภาระต่อฮาร์ดแวร์ของผู้ใช้ |
| **ค่าใช้จ่ายและโครงสร้างราคา** | ฟรี ไม่มีค่าใบอนุญาตหรือข้อจำกัดด้านขนาดข้อมูลและจำนวนหน้ากระดาษ | มีข้อจำกัดเรื่องเครดิตหน้าในการประมวลผล (คิดค่าใช้จ่ายต่อหน้าหรือระบบโควตาสมาชิก) |
| **การปรับใช้นอกแพลตฟอร์ม** | ทำได้สะดวกโดยดาวน์โหลดไฟล์ `.mlmodel` ไปใช้กับคำสั่ง Kraken CLI [1] นอกรอบ | ค่อนข้างซับซ้อน เนื่องจากระบบเชื่อมโยงกับ Transkribus Ecosystem เป็นหลัก |
| **ความเหมาะสมเชิงเนื้อหา** | เหมาะกับสถาบันที่มีทีมสารสนเทศคอยสนับสนุน มีข้อจำกัดทางกฎหมายด้านข้อมูล | เหมาะกับทีมวิจัยขนาดเล็กถึงกลางที่ต้องการความสะดวก รวดเร็ว และไม่มีสถาปัตยกรรมเซิร์ฟเวอร์ |

ในแง่ประสิทธิผลต่องานสืบค้นเอกสารโบราณอักษรขอมบนใบลานและอักษรไทยบนสมุดไทยโบราณ eScriptorium มอบความเป็นอิสระสูงสุดแก่นักวิชาการในการดัดแปลงคอร์ปัสและปรับแต่งแนวเส้น Baseline ด้วยสิทธิความยืดหยุ่นที่ไม่มีขอบจำกัดทางลิขสิทธิ์ ในทางตรงกันข้าม สำหรับนักวิจัยที่มีข้อจำกัดด้านความพร้อมของเทคโนโลยีสารสนเทศ การพึ่งพาโครงสร้างระบบคลาวด์และโปรแกรมตรวจวิเคราะห์สำเร็จรูปที่เสถียรอย่าง Transkribus ก็นับเป็นทางเลือกหลักที่ช่วยให้โครงการสามารถบรรลุเป้าหมายการปริวรรตจดหมายเหตุระดับชาติได้อย่างมั่นใจภายใต้เวลาที่กำหนด การเลือกแพลตฟอร์มใดแพลตฟอร์มหนึ่งจึงไม่เพียงอาศัยเกณฑ์ความละเอียดทางเทคนิค แต่คือการปรับสมดุลวิชาการระหว่างค่าใช้จ่ายการดูแลระบบ ความง่ายของอินเทอร์เฟซ และความมั่นใจในนโยบายลิขสิทธิ์และการเก็บรักษาข้อมูลของสถาบันตนเองอย่างยั่งยืน
